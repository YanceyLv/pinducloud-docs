# 创建 MiniMax-H3 视频再生成任务

再生成接口把符合 MiniMax-H3 768P 输出规格的源视频生成成 2K 视频。它不是任意
视频转码接口，输出分辨率固定为 2K，输出时长继承源视频。本站会先校验源任务
归属和源任务状态，再处理源任务关联。

## 请求

~~~http
POST https://video.pinducloud.com.cn/hailuo/v2/video_regeneration
~~~

请求必须且只能选择一种源视频模式：

- source_task_id：引用当前用户自己创建的 H3 768P 成功任务。
- content：直接提交一个 role=base_video 的源视频，并带上生成源视频时的输入。

两个字段同时出现，或两个字段都不出现，都会返回参数错误。`duration` 不控制
再生成时长，输出时长继承源视频；`resolution` 必须为 `2K`。

## 模式一：源任务 ID

~~~bash
curl --request POST "$BASE_URL/hailuo/v2/video_regeneration" \
  --header "Authorization: Bearer $API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "model": "MiniMax-H3",
    "source_task_id": "task_gateway_h3_768p_01",
    "resolution": "2K",
    "aigc_watermark": false
  }'
~~~

参数要求：

- model 必须为 MiniMax-H3。
- source_task_id 必须属于当前用户，源任务必须成功、是普通 H3 生成任务，且
  分辨率为 768P。
- 源任务需要处于服务端可查询窗口内；部分功能可能需要额外授权。
- resolution 必须写 2K。
- 此模式不需要 `content` 或 `duration`，时长来自源任务。
- 不能同时提交 content、prompt、images、image 或 input_reference。

服务端会用公开任务 ID查找并验证源任务，再处理再生成请求。

## 模式二：直接传入源视频

~~~bash
curl --request POST "$BASE_URL/hailuo/v2/video_regeneration" \
  --header "Authorization: Bearer $API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "model": "MiniMax-H3",
    "content": [
      {"type": "text", "text": "保留原有动作，改成黄昏光线并使用更宽的镜头"},
      {
        "type": "video_url",
        "role": "base_video",
        "video_url": {"url": "https://cdn.example.com/source-768p.mp4"}
      },
      {
        "type": "image_url",
        "role": "reference_image",
        "image_url": {"url": "https://cdn.example.com/style.png"}
      }
    ],
    "resolution": "2K"
  }'
~~~

content 必须包含恰好一个 `base_video`，且该项的 `type` 必须是 `video_url`。
还必须有一个非空 `text` 项。其他参考媒体可以按生成接口的规则继续提供，但帧图
角色与 `reference_*` 角色不能混用。

为保持再生成结果与源视频一致，文本应使用生成 768P 源视频时实际送入模型的
最终 prompt；如果之前调用过 Context-IR，应使用增强后的 task.content.prompt。
参考图片、参考视频和参考音频应与源任务保持一致。

## base_video 源视频规格

源视频必须满足 MiniMax-H3 的 768P 输出约束：

| 项目 | 要求 |
| --- | --- |
| 音轨 | 必须包含音轨，无音轨视频不支持 |
| 帧率 | 24 FPS |
| 宽和高 | 都能被 32 整除 |
| 面积 | 不超过 768 × 1344（1,032,192 像素） |
| 总帧数 | 107~362 帧，每档递增 17 帧 |
| 时长 | 约 4~15 秒，具体由帧数决定 |

源视频的 URL必须能被服务端访问。PinduCloud 不会把本地文件路径转换成公网地址，
也不能用 multipart 上传代替 `base_video`。服务端校验内容结构，源视频的编码、尺寸、
帧率、音轨和帧数会在任务提交后继续检查。

额外的 `reference_video` 帧率应在 23.976–60 FPS 范围内，与 `base_video` 的
24 FPS 要求分别校验。提交前应检查媒体元数据；满足单项要求不代表所有素材检查
均已通过，具体失败原因由任务查询结果中的 `task.error` 返回。

已有产物的下载 URL 不保证能再次被上游读取。签名有效期、访问权限及上游的
网络访问限制均可能影响媒体获取。若返回 `media URL cannot access a private address`，
表示上游拒绝访问该地址，应检查地址及重定向目标，或将视频转存到上游可访问的
对象存储。已有符合条件的 H3 任务时，优先使用源任务 ID 模式；使用内容模式时，
媒体地址的有效期应覆盖排队和处理过程。

提交返回任务 ID 不代表素材校验已通过。素材错误可能在后续查询中以 `failed`
返回，应读取 `task.error`，并通过消费及退款日志核对预扣费用的处理结果。

## 顶层参数

| 字段 | 类型 | 必填 | 取值或范围 | 说明 |
| --- | --- | --- | --- | --- |
| model | string | 是 | MiniMax-H3 | 固定模型 |
| source_task_id | string | 二选一 | 当前用户的 H3 768P 任务 | 源任务模式 |
| content | array | 二选一 | 含一个 `base_video` | 直接内容模式 |
| resolution | string | 是 | 2K | 再生成固定输出 2K |
| callback_url | string | 否 | 公网可访问地址 | 状态变化回调 |
| aigc_watermark | boolean | 否 | true / false | 是否添加 AIGC 水印 |

## 成功响应

~~~json
{
  "task_id": "task_gateway_h3_regen_01"
}
~~~

再生成任务的查询结果将 `task_type` 标为 `regeneration`，源任务模式和内容模式
均使用再生成价格规则。费用按上游返回的计费用量及本站价格设置结算。

可选回调的实际行为见[回调地址](./create#回调地址)：创建成功不保证回调可达，
应保留查询任务的能力。

## 小数时长与结算

视频文件时长与计费秒数可能不同。本站按上游返回的 `usage.output_seconds`
结算，不按下载文件的小数时长重新计量。计费用量可能按整数秒返回；例如文件
时长为 5.166667 秒，而 `output_seconds` 为 6 时，按 6 秒结算。每个任务应以
其返回的实际计费用量为准，不应仅根据文件时长自行推算。

例如再生成单价配置为 $0.30/秒、没有额外媒体费用时，该任务费用为
`6 × $0.30 = $1.80`。这是计算示例，不是固定价目。直接内容模式在提交时未知
源视频用量，可能按上限预扣；完成后按实际用量结算差额。如果本例预扣 $4.50，
最终费用为 $1.80，则退回 $2.70。预扣金额不应当作最终消费金额。
